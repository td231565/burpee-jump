IOS 實機教學

在自己的 iPhone
免費安裝 Release App

使用 Mac、Xcode 與免費 Apple Account，把 BurpeeJump 編譯成包含正式模式程式碼的 App，直接安裝到自己的手機。

這份教學的終點 手機主畫面出現獨立的 BurpeeJump 圖示；拔掉連接線、關閉 Expo 開發伺服器後，App 仍能自行開啟。

開始之前

先釐清「Release」與「免費簽署」

Release 指 App 以正式模式編譯，JavaScript 和資源包進安裝檔，不靠 Expo Go 或正在運作的 Metro 伺服器。免費 Personal Team 則是讓 Xcode 在你自己的 iPhone 上安裝這個建置的簽署方式。

這個 App 適合做實機功能與啟動效能測試；它不是可分享下載連結的 EAS Ad Hoc 建置，也不是可上傳 App Store 的發佈簽署檔。

免費帳號的有效期限

Apple 的免費 Personal Team 佈建描述檔 7 天後到期，之後須重新建置並安裝。免費帳號也有 App ID、裝置與已安裝 App 數量限制。這不影響本次短期實機測速。

01 / 準備

開始前確認這些條件

  • 一台可執行目前 Xcode 的 Mac，並已安裝 Xcode 與 iOS 開發元件。
  • 自己的 iPhone、可傳輸資料的連接線，以及可在 Xcode 登入的免費 Apple Account。
  • Mac 上已有 BurpeeJump 專案、Node.js 與 Bun；專案套件可正常安裝。
  • iPhone 已解鎖，能接受「信任這部電腦」與開發者模式提示。

先在終端機確認 Xcode 命令列工具可用：

xcodebuild -version
xcode-select -p
bun --version

若 xcode-select -p 指向 Command Line Tools 而非 Xcode，先在 Xcode 的 Settings → Locations → Command Line Tools 選擇已安裝的 Xcode。還要對照 Apple 的 Xcode 裝置支援表，確認這版 Xcode 能支援 iPhone 的 iOS 版本；Xcode 太舊時，裝置可能一直顯示 Reconnecting。

02 / 操作步驟

從原始碼到手機主畫面

1

在 Xcode 登入免費 Apple Account

開啟 Xcode，進入 Xcode → Settings → Apple Accounts 並登入。沒有付費會員資格時，Xcode 會顯示 Personal Team。後續簽署要選這個 Team。

2

連接並配對自己的 iPhone

用線連接 Mac，解鎖 iPhone，遇到「信任這部電腦」時選擇信任。Xcode 若要求配對或準備裝置，依畫面完成。第一次配對可能需要等候。

確認方式：在 Xcode 的執行目的地選單打開「Manage Devices…」，或從 Xcode → Open Developer Tool → Device Hub 開啟裝置中心。iPhone 出現在側欄的 Available 下、畫面顯示「View Screen」，並且能在 Xcode 的執行目的地選單選到它，就代表配對完成。若仍顯示 Pair 或準備中，依畫面完成後再檢查。

3

開啟 iPhone 的開發者模式

在 iPhone 前往 設定 → 隱私權與安全性 → 開發者模式，開啟後依提示重新啟動並確認。若看不到該選項，先完成上一個步驟的 Xcode 配對，再回來查看。

4

在 BurpeeJump 專案安裝依賴

在終端機切換到自己的 BurpeeJump 專案資料夾。專案使用 Bun；若已存在可用的 node_modules，可略過安裝。

cd /你的專案路徑/BurpeeJump
bun install --frozen-lockfile

路徑中的「你的專案路徑」是提示文字，請換成實際位置。也可在 Finder 把資料夾拖進終端機，取得正確路徑。

5

設定專屬 Bundle Identifier

編輯專案的 app.json，在 expo.ios 內加入 bundleIdentifier。名稱要由你自行選擇且足夠獨特；下面只是格式範例，不要直接照抄 example。

"ios": {
  "supportsTablet": false,
  "bundleIdentifier": "com.你的識別名稱.burpeejump"
}

Bundle Identifier 決定手機如何辨識 App。若之後更換它，iPhone 會把新建置視為另一個 App，既有本機資料也不會自動搬過去。

6

編譯 Release 並安裝到手機

保持 iPhone 解鎖且連接，於 BurpeeJump 專案目錄執行：

npx expo run:ios --configuration Release --device

從清單選擇實體 iPhone。第一次執行時，Expo 會產生 iOS 原生專案、安裝必要的原生依賴，再交由 Xcode 編譯及安裝。Release 會把正式模式程式碼包進 App，無須另外啟動 expo start。

如果出現簽署錯誤，先照下一步在 Xcode 設定 Personal Team，然後重新執行本命令。

7

簽署失敗時，用 Xcode 重新取得佈建描述檔

若終端機出現 No profiles for 'com.richardisrich.burpeejump' were found、Automatic signing is disabled，或免費簽署到期後重裝失敗，先依下列步驟讓 Xcode 處理簽署。上述安裝命令執行後會有 ios 原生目錄；在 Mac 終端機的 BurpeeJump 專案目錄執行：

xed ios/BurpeeJump.xcworkspace

開啟 BurpeeJump.xcworkspace，讓 Xcode 一起載入 App 與 Pods 依賴。

  1. 在 Xcode 左側按資料夾圖示，顯示 Project navigator（快捷鍵 ⌘1）。
  2. 點左側最上層、藍色專案圖示旁的 BurpeeJump 名稱。其下灰色的 BurpeeJump 資料夾是原始碼；側欄另一個藍色圖示的 Pods 是依賴專案，簽署設定要從 BurpeeJump 進入。
  3. 中間偏左會出現 PROJECT／TARGETS 清單。點 TARGETS 底下的 BurpeeJump，選到 App target。
  4. 在右側上方點 Signing & Capabilities 分頁，再點內容上方的 All（旁邊是 Debug、Release），讓設定涵蓋 Release。
  5. 勾選 Automatically manage signing，將 Team 設為原本使用的 Personal Team。若沒有自己的 Team，先到 Xcode → Settings → Apple Accounts 確認登入。
  6. 確認 Bundle Identifier 與 app.json 相同；本專案目前為 com.richardisrich.burpeejump。更新既有 App 時維持原本的識別碼與 Team。
  7. 保持手機連接且解鎖，在 Xcode 頂端、BurpeeJump scheme 旁的裝置選單選自己的實體 iPhone（例如 RichardIphone）。等待簽署處理完成；若出現 Try Again／Register Device／Set Up Signing，依當下提示操作。
  8. 確認簽署區域不再有紅色錯誤，並顯示 Provisioning Profile：Xcode Managed Profile 與 Signing Certificate：Apple Development…，再回到 Mac 終端機重新執行下方命令。

如何辨認選錯 Pods？

如果中間的 TARGETS 清單出現 EXConstants、ExpoAudio、hermes-engine、Pods-BurpeeJump 等大量項目，表示目前選到 Pods。回到左側最上層的 BurpeeJump 藍色專案圖示，再選 TARGETS → BurpeeJump。

npx expo run:ios --configuration Release --device

這是終端機命令。在裝置清單選自己的 iPhone，等待編譯及安裝完成；只看到 JavaScript 打包完成或 Auto signing app using team(s)，還不代表手機已安裝新版。保留手機上的舊 App，直接覆蓋安裝，以保留本機訓練紀錄。

若 Xcode 仍顯示簽署錯誤，依簽署區域的具體訊息處理；某個 capability 不支援免費帳號時，須處理該能力或改用付費會員。若終端機提到 -allowProvisioningUpdates，它是 xcodebuild 的參數，不能直接接在上述 Expo 命令後面。

03 / 確認結果

如何知道裝的是獨立 Release App？

  1. 在 iPhone 主畫面找到 BurpeeJump 圖示，從圖示開啟；不經過 Expo Go 的專案清單。
  2. 在 Mac 關閉 Metro／Expo 開發伺服器，拔掉連接線，再從手機圖示重新開啟。
  3. App 能進入 BurpeeJump 的首頁或首次引導頁，且不要求連接開發伺服器。

成功標準

能獨立啟動並進入可操作畫面。請保留本次使用的 iPhone 型號、iOS 版本與原始碼版本，之後測效能才容易比較。

04 / 效能測試

接著測啟動時間

安裝成功後，測速時從手機主畫面點 BurpeeJump 圖示開始計時，並區分「首次畫面出現」與「首頁可操作」。BurpeeJump 會初始化 SQLite 並載入引導狀態，畫面上出現載入指示器不代表首頁已可用。

  • 冷啟動：完全結束 App 後重開；記錄多次測量結果。
  • 返回 App：切到其他 App，再返回 BurpeeJump；與冷啟動分開記錄。
  • 首次安裝：第一次資料庫初始化與首次引導另列，不與回訪首頁混合比較。

手動錄影可做初步檢查；需要可比較的精確數值時，使用 Xcode／Instruments 的啟動效能工具，並記錄裝置與測試條件。

排查

卡住時先看這裡

命令找不到實體 iPhone

確認手機已解鎖、線材可傳輸資料、已選擇信任 Mac，且 Xcode 已完成裝置配對。重新執行 npx expo run:ios --configuration Release --device，在清單選實體裝置。

出現 Signing、Provisioning 或 Team 錯誤

依照第 7 步：用 Xcode 重新取得佈建描述檔，選 BurpeeJump 專案的 App target，確認 All、自動簽署與 Personal Team。若 TARGETS 出現大量 Expo／React 套件，表示選到 Pods，請回到側欄最上層的 BurpeeJump 專案。

iPhone 找不到「開發者模式」

先連接 Mac 並透過 Xcode 啟動配對。Apple 說明開發者模式選項可能要在開始配對後才會出現；開啟時需重開機並再次確認。

一直顯示 Reconnecting，並出現 developer disk image／0xe800010f

先比對 iPhone 的 iOS 版本與 xcodebuild -version。這種錯誤可能表示目前 Xcode 缺少該裝置所需的開發映像。依 Apple 的 Xcode 裝置支援表，更新到支援該 iOS 的 Xcode；若新版 Xcode 要求更高版本 macOS，先更新 macOS。更新後重新開啟 Xcode、重接手機，再等待裝置完成準備。不要先刪除 DeveloperDiskImages 或反覆重建 BurpeeJump。

App 一週後打不開，或顯示「BurpeeJump 無法再使用」

免費 Personal Team 的安裝授權約 7 天到期。保持相同 Bundle Identifier 與 Team，重新建置並覆蓋安裝；先保留手機上的 App，以免遺失本機紀錄。若重裝時找不到佈建描述檔，依照第 7 步先在 Xcode 處理簽署，再回終端機執行 Release 安裝命令。

看到 Expo 開發選單或要求 Metro

檢查是否誤裝 Debug／development build，或從 Expo Go 開啟專案。用 --configuration Release 重建，並從 BurpeeJump 的獨立圖示開啟。
