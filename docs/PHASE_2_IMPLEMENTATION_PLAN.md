## 1. 交付目標

在既有「首頁 → 四組計時 → 保存 → 日曆」閉環上加入固定 7／14／30 天挑戰、限次休息、隔日補登、復歸與一次性結算。每日訓練及休息紀錄獨立於挑戰結果；不新增忙碌模式或單組完成。

挑戰資料、每日紀錄、由休息日推導的剩餘額度與是否已結算必須在重啟後一致。剩餘額度不另存可變欄位；結算結果僅於當下顯示一次，不提供歷史結果或結算後重算。

## 2. 已定案的資料與操作契約

### 挑戰建立與週期
- 挑戰在建立當地日開始，連續 7／14／30 日，休息不順延。
- 週期內不可新建挑戰；結束隔天先嘗試結算舊挑戰，結算標記寫入失敗亦不阻擋建立新挑戰。建立當天已有四組完成紀錄時直接計入。
- 建立資格僅依賴挑戰日期範圍，不依賴舊挑戰結算標記是否已成功入庫。

### 每日狀態與連續天數
- 每日僅有四種可見狀態：已完成、休息日、今天待完成、過去無紀錄；未來日期無狀態。
- 已完成必須為完整四組成功儲存；同日「再做一次」不記錄。
- 連續訓練天數僅計入已完成日；休息日維持連續性但不累加天數，無紀錄日即中斷。今天待完成時先顯示截至昨天的天數。

### 休息額度與取消契約
- 額度為 7／14／30 天各 1／2／3 次；對外不區分休息來源，僅保存設定時間以判斷取消期限。
- 已儲存訓練的日期不可設定休息。取消休息時退還額度。
- **當日休息**：於當日結束前可取消；若當日休息後又成功儲存四組訓練，由該筆訓練交易自動覆蓋休息紀錄並退還額度。
- **昨天補登休息**：於補登當日結束前可取消；不能由後續訓練覆蓋。

### 結算流程與補登詢問
- **觸發時機與畫面保護**：
  - 挑戰最後一天結束後，於隔天 00:00（App 在前景）或下次進入前景時檢查結算。
  - 若使用者正處於日期詳情或其他畫面，待操作結束並返回首頁才顯示，避免中途以滿版畫面打斷。
  - 跨午夜仍在進行或待儲存之訓練延後至結果確定才結算。
- **補登挽救詢問（一般對話框）**：
  - **觸發條件**：僅在最後一天是昨天、無完成或休息紀錄、尚有剩餘額度，且其他所有挑戰日皆有完成或休息紀錄時觸發。
  - **對話框互動**：以「要不要將昨天登記為休息日呢？」詢問，明示消耗一次額度且結束日不變，僅有「是／否」選項。點擊背景或系統返回鍵不關閉。
  - **選擇結果**：
    - 選「否」：依現有紀錄立即結算，不再詢問。
    - 選「是」：寫入休息紀錄後再進入結算；若寫入失敗則保留重試及改選「否」的入口，不提前結算。
    - 期限防呆：若畫面停留至補登期限過後才按「是」，不寫入休息紀錄，直接依現有紀錄結算。
    - 未作答中斷：若未作答即關閉 App 則暫不結算；下次進入前景若仍在期限內則再次詢問，期限已過則直接結算。
- **滿版結算畫面**：
  - 若不符合補登詢問條件（例如已有過期無紀錄日），直接判定二元結果（已完成／未完成）。
  - 顯示畫面**前**必須先持久化「已結算標記」，避免重啟後重複顯示。已結算標記寫入成功後，即使用戶未看過或中斷關閉 App 亦視為已結算。
  - 結算後若發生合法的補登或取消，僅更新每日紀錄與連續天數，不修改已確定顯示的一次回合結果。

### 日曆呈現
- 僅標示進行中挑戰範圍、起迄日、剩餘休息額度與連續訓練天數；不顯示百分比、分類統計、歷史挑戰結果或每日挑戰成敗。跨月沿用單一月曆。

D-053 覆蓋 D-001 的補登休息專屬標記、D-003 的百分比與結算後重算，以及早期忙碌模式的範圍。D-007、D-016 的當地日與按「開始」鎖定歸屬日規則仍有效。

## 3. 範圍

### 納入

- 三種固定挑戰週期、當天建立、週期內不可重建及結束隔天可建立下一個。
- 完整四組訓練與原有日期鎖定、儲存重試、不記錄再次訓練路徑。
- 限次休息、當日設定／取消、昨天補登／取消及額度退還。
- 漏做後的溫和復歸、連續訓練天數與每日狀態。
- 進行中挑戰日期範圍標示、起迄日、剩餘休息額度與一次性二元結算。
- SQLite 持久化、跨日／跨月／重啟一致性、iOS／Android 無障礙驗收。

### 不納入

- 忙碌模式、最低完成、完成百分比、「第幾天／共幾天」式週期進度數字、模式分類統計、徽章收藏、挑戰結果歷史畫面、結算後重算。首頁的「挑戰還有 x 天」是剩餘天數提示；結算畫面的金色徽章僅為一次性視覺圖案。
- Phase 3 通知、震動、Lottie、理由或障礙備案；Phase 4 自訂秒數、組數與背景計時；之後階段的身體數據、帳號、同步或社交。
- 任意歷史日補登、超額休息、同日再次訓練統計；現有「再做一次」仍不記錄。

## 5. 垂直切片與驗收

每片先寫公開行為測試，再做最小實作；前片通過後才進下一片。

### Slice 0：資料契約與案例

1. 固定日期狀態與合法操作表；驗證今天待完成、過去無紀錄、已完成、休息日及未來無狀態。
2. 用 7／14／30 天例子固定起迄日、1／2／3 次額度、跨月、跨午夜、取消與退還。
3. 固定一次性結算及結算後每日紀錄可變的案例，涵蓋結算前補登、結算後補登／取消、跨午夜待儲存。
4. 保留既有 daily_completions，以交易完成 schema 變更並驗證升級前後紀錄一致；開發驗收時另存測試資料庫備份，不建立 App 內備份功能。

**驗收：** 每個例子可唯一判定每日顯示、剩餘額度、連續天數、結算時點與當下結果。

### Slice 1：建立挑戰與持久化

- **前置狀態與入口**：
  - 首頁提供「開始挑戰」入口；無進行中挑戰時開放。
  - 今日紀錄讀取失敗時停用入口，重新載入成功後才開放。
  - 同期不可建立第二個挑戰；舊挑戰結束隔天即可建立，不論舊挑戰結算標記是否已成功入庫。
- **獨立畫面與週期選擇**：
  - 進入獨立畫面選擇 7／14／30 天，各選項標示 1／2／3 次額度，並明示「挑戰開始後，不能中途取消」，不顯示預計起迄日區塊。
  - 今日已完成時沿用首頁狀態，開始挑戰畫面不重複顯示「將計入第 1 天」。
- **提交點擊校驗**：
  - 按下「開始挑戰」即直接以當下裝置當地日建立，不顯示二次確認，亦無多階段日期刷新；建立後不提供撤銷或取消挑戰入口。
- **建立後呈現**：
  - 建立成功後直接返回首頁，以「挑戰還有 x 天，剩餘休息 y 天」顯示摘要（x 包含今天，最後一天為 1，結束隔天移除；y 依額度與已設休息日推導）；不另設成功頁、結束日期或進度百分比。
  - 建立當天已有四組完成紀錄直接計入。
- **測試**：交易及 repository 測試涵蓋重啟、既有完成紀錄保留及週期日期。

### Slice 2：完整訓練與每日紀錄

- 挑戰期間沿用唯一四組訓練流程，不出現模式選擇。保存成功後日曆顯示已完成；失敗時不計入，重試成功僅一筆。
- 同日「再做一次」不寫入或升級每日完成紀錄；跨午夜歸屬日沿用 D-016。

### Slice 3：限次休息與取消（當日操作）

- **設定前置與觸發點**：
  - 首頁於主要訓練按鈕旁提供「把今天設為休息日」次要入口。
  - 僅限尚未儲存訓練且額度 > 0 之挑戰日；點擊直接保存並更新狀態與額度，不跳二次確認。
  - 額度為 0 且今日未完成時，首頁顯示不可點擊的「休息額度已用完」；該日完成紀錄讀取失敗時停用按鈕。
- **當日取消**：
  - 設定成功後同一位置改為「取消休息」；當日結束前可取消並退還額度。設定時間支援重啟後之期限判定。
- **訓練覆蓋機制**：
  - 當日設為休息後，主要訓練按鈕保持可點擊。
  - 歸屬當日的訓練若成功儲存四組，系統在同一筆交易中自動轉為完成日、移除休息紀錄並退還額度，無須手動取消休息。跨午夜成功儲存仍適用此規則。
  - 中途取消或未成功儲存則保留休息日與額度；任一步失敗皆不生效。
- **UI 呈現**：日曆與日期詳情以文字加圖示／形狀區分已完成與休息日，不只靠顏色。

### Slice 4：補登、取消與復歸（隔日操作）

- **補登前置與觸發點**：
  - 觸發入口僅在日曆日期格進入的既有「日期詳情」畫面（首頁不設補登入口）。
  - 僅限「昨天」、無完成紀錄且原挑戰尚有剩餘額度時可補登；更早日期或已有完成紀錄之日期不可補登。
- **日曆待處理提示（閃爍圓點）**：
  - 僅在該日有待處理且可執行之操作（如昨天符合補登條件）時顯示於日期格；僅能查看詳情時不顯示。
  - 保持「無紀錄」每日狀態；螢幕閱讀器說明「可補登休息」；查看詳情不清除，完成或過期才移除；系統啟用減少動態效果時保持常亮。
- **補登操作與取消**：
  - 日期詳情內提供「將昨天設為休息日」按鈕，點擊後彈出確認對話框（明示消耗額度與固定結束日）。
  - 補登成功後於日曆顯示「休息日」；補登當日結束前可在日期詳情內取消並退還額度。
- **復歸與連續天數**：
  - 昨天無紀錄時首頁提供溫和復歸入口。連續訓練天數在休息與無紀錄情境正確重算，過去完成紀錄保留。

### Slice 5：日曆與一次性結算

- **日曆展示**：僅顯示進行中起迄日、剩餘額度、當月可見之範圍標記與「已連續訓練 x 天」；結束後移除標記，不顯示歷史結果。跨月沿用單一月曆。
- **結算檢查與畫面防打斷**：
  - 最後一天結束隔天 00:00 前景或下次進入前景時檢查結算。
  - 使用者在操作其他畫面（如日期詳情）時不打斷，待回到首頁才顯示。跨午夜訓練延後結算。
- **補登挽救對話框**：符合唯一挽救條件時（僅最後一天無紀錄且有額度，補登後可全滿），先彈窗詢問「是／否」；選「否」直接結算；逾期或關閉 App 依契約防呆處理。
- **滿版結算畫面**：
  - 顯示前必須先持久化「已結算標記」，重啟不重顯；即使標記寫入後關閉 App 亦視為結算完成。
  - 視覺：暗色背景、中央靜態 SVG、下方小字「跳過」。
  - 動效：0.8 秒淡入放大後靜態；結束 0.3 秒後顯示「回到首頁」；點擊「跳過」直接關閉。
  - 減少動態效果：直接顯示靜態圖案與結果，立即提供「回到首頁」，無進場動畫與延遲。
- **標記寫入失敗之容錯與背景重試**：
  - 標記寫入失敗不阻擋建立新挑戰。
  - 寫入失敗時以非阻擋式 Toast「挑戰結算中」告知（同一次 App 執行至多 1 次；記憶體旗標不入庫；重新啟動若未建新挑戰且重試仍失敗可再顯示 1 次）。開始新挑戰後，舊挑戰重試失敗不再提示。
  - 下次進入前景自動查找並重試入庫；若已有新挑戰，舊挑戰僅補標記而不補顯結果。
  - 首次寫入失敗後至開始新挑戰前的合法補登／取消，重試時以最新紀錄重算結果。
- **結算後異動**：結算後合法補登或取消僅更新每日紀錄與連續天數，不改動已顯示之二元結果。
